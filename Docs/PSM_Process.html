How a change reaches production

  1. Edit & signOn this PC; Set-ScriptSignature. Bump the app's Version.
  2. Preview & PublishSetupApplications → Publish to DFS. Backup first, signed scripts only.
  3. Release updatedChanged files only; removed files moved to _Retired; Release.json.
  4. Servers pullWithin the hour each Frontend copies what changed for its apps.
  5. Servers report"Synced" record to DFS; Backend updates Inventory.json within 15 min.

Need it on one server now? Use the "Copy to servers" tab: it copies directly and the next hourly pull finds nothing to change.

APP-PowershellScriptsManagementComputer accounts of the servers (OU=ApplicationsGroups)— nested in the two groups above

The Frontend runs as SYSTEM, which reaches DFS as the computer account (SRVxxxx$). Group changes count only after a reboot or a ticket purge.

Safety rules

What moves

  • Only validly signed scripts are published or pulled.
  • Files are compared by SHA256; only changed files move.
  • Written under a temporary name, then renamed — never half a file.
  • A publish always makes a backup of C:\SCRIPTS first.

What never moves

  • Server-local data: DynamicGroups rules, PoshAcme certificates, logs, transcripts.
  • Nothing is deleted on a server; removed files on DFS go to _Retired\<date>.
  • Nothing outside C:\SCRIPTS is written by the Frontend.
Publish before enabling a Frontend. A Frontend makes its server match DFS. If DFS is older than the server, the server is rolled back (this happened on SRV010010050050 on 2026-10-20 before the first publish).

Adding a server

  1. Add its computer account to APP-PowershellScriptsManagement.
  2. On the server (elevated), refresh its tickets — use the full path, another klist may be first on PATH: 
    C:\Windows\System32\klist.exe -li 0x3e7 purge
  3. SetupApplications → Copy to servers: copy the server's applications (Base and the PSM Frontend come along).
  4. On the server: C:\SCRIPTS\Applications\PSM\FrontendScriptsSync\Install-FrontendScriptsSync.ps1
  5. Check C:\SCRIPTS\Logs\Sync-ScriptsFromDfs.log shows 0 failed and its records on DFS show Synced OK.
